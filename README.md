这是**属于你自己的**陪玩预约网站，功能和你朋友那套对齐，但代码只有 6 个文件、零第三方依赖，
每一行都写了中文注释，就是给你学着改的。

## 三、第一次使用，按这个顺序做

1. **改密码**：后台 →「安全与备份」→ 修改管理密码（至少 6 位）。
2. **填资料**：后台 →「资料与报价」，名字、微信号、闲鱼链接、自我介绍、报价档位。
   现在里面预置的是你那套内容，直接改字就行。
3. **设固定休息**：后台 →「预约与时间」→ 固定休息规则 → 建议第一条填
   `每天 02:00 – 10:00`，备注「睡觉休息」。不加这条，你的时间表会显示全天 24 小时都能约。
4. **收预约**：客户在主页选好时间 → 生成一段文案 → 复制发到你微信 → 你确认后，
   在后台点那几格把它们**锁定**成「预约」。
5. **传展示墙**：「展示墙」标签页，传 3–5 张截图或老板评价，勾选「保存后立即公开」。

## 四、核心概念（看懂这 5 条，网站就全懂了）

### 1. 一个格子有 5 种状态

| 状态 | 含义 | 谁能改 |
|---|---|---|
| `free` 可预约 | 空着，客户能点 | 自动 |
| `booking` 已预约 | 被你锁定的单子 | 后台锁定 |
| `rest` 休息 | 被「固定休息规则」或手动休息覆盖 | 后台 |
| `past` 已过去 | 这个小时已经过去了 | 自动（按时间算） |
| `closed` 停接 | 你关掉了「开放接单」总开关 | 后台一个勾 |

判断顺序写在后端 `slot_status()` 里：**先看是否过去 → 再看是否被锁定 → 再看规则 → 再看总开关**。
想改哪个优先，就调这个函数的顺序。

### 2. 时间表怎么来的

`build_slots()` 每次请求都现场生成 **今天 0 点起、未来 7 天 × 24 小时 = 168 个格子**。
它不是存在数据库里的，而是"**用规则算出来的**"——所以你改一条休息规则，整周时间表立刻变。

> 想改成显示 14 天？把 `app.py` 里的 `DAYS_SHOWN = 7` 改成 14 就行。

### 3. 为什么没有"订单"和"支付"

这是**故意**的，和你朋友那套一样的思路：客户选完时间，网站只生成一段微信文案给他复制，
**你确认后手动锁定**。好处是：

- 不会出现"客户随便点一下就占了你 3 小时"
- 不需要接支付、不需要处理退款
- 想放鸽子、改时间，微信上说一句就行

代价是：你的**微信是唯一的成交通道**，所以主页那个"复制微信号"按钮很重要。

### 4. 后台只有 4 张表

- `store`：放你的资料（JSON）和密码（加盐哈希，数据库里看不到明文）
- `locks`：被锁定的时段（`kind` 是 `booking` 预约 / `rest` 休息）
- `rules`：固定休息规则（按周重复，支持跨午夜）
- `gallery`：展示墙

### 5. 登录是怎么做的

登录成功后服务端发一个 Cookie，里面是「过期时间 + 用密码哈希签名的指纹」（`HttpOnly`，JS 读不到）。
**服务器不保存任何会话**——所以你重启网站、重新部署，只要 Cookie 没过期就还是登录状态；
而你一改密码，签名密钥跟着变，所有旧 Cookie 立刻失效。有效期 12 小时。

## 五、数据、备份、恢复

> **先记住这一条**：免费的 Render 实例**每次休眠（15 分钟没人访问）都会清空 `data/`**。
> 解决和缓解办法写在 [DEPLOY.md](DEPLOY.md) 的「最重要的一节」：定时保活 / 挂持久磁盘 / 勤导出备份。
> 后台会在你超过 7 天没导出备份时弹提醒。

- 所有数据在 `data/site.db`（SQLite 单文件）+ `data/uploads/`（图片）。
  旁边可能还有 `site.db-wal`、`site.db-shm` 两个文件——那是 SQLite 的并发日志，**别删**，
  它们和 `site.db` 是一套的（备份时用后台的「下载备份 JSON」，不要直接拷 .db 文件）。
- 后台「安全与备份」→「下载备份 JSON」导出**全部**业务数据：资料、预约时段、休息规则、展示墙，
  **连展示墙图片也一起打包在里面**（单张超过 3MB 的图不会打包，避免备份文件太大）。
- 后台「安全与备份」→「从备份恢复」可以把备份**整个写回去**，图片也会重新生成。
  这是给免费 Render 实例准备的：**它每次重新部署都会清空 `data/`，先导出一份就不会白干**。
- 换电脑/重装：把 `data/` 整个文件夹拷过去就行。
- 想清空重来：关掉网站，删掉 `data/` 文件夹，再启动（会重新生成默认资料）。

## 六、部署到 Render（让它上公网）

> 完整的、带你点完每一步的版本在 [DEPLOY.md](DEPLOY.md)，下面是提要。

### 性能参考（我实测的）

- `/api/public`（时间表数据）平均 **4.4 毫秒**，首页 HTML 约 7 KB
- 首屏一共下载 **约 161 KB**（HTML + CSS + JS + 默认背景图）
- 免费实例每月含 5 GB 流量 → 大约可支撑 **3 万次访问**，个人陪玩站完全够用

### 第 1 步：把代码传到 GitHub

```bat
cd peiwan-site
git init
git add .
git commit -m "我的陪玩预约站"
git branch -M main
git remote add origin https://github.com/你的用户名/peiwan-site.git
git push -u origin main
```

> 建议加一个 `.gitignore`，把 `data/` 排除掉（里面有你的业务数据和密码哈希）。

### 第 2 步：在 Render 建服务

1. 打开 <https://dashboard.render.com/web/new>
2. 选 **Git Provider** → 授权 GitHub → 选中你刚推的仓库
3. 填：
   - **Name**：`peiwan-site`（会变成 `https://peiwan-site.onrender.com`）
   - **Region**：`Singapore`（离国内最近）
   - **Language**：`Python 3`
   - **Build Command**：`echo 零依赖，无需构建`
   - **Start Command**：`python app.py`
   - **Instance Type**：先选 `Free`
4. **Advanced → Environment Variables** 加两条：
   - `ADMIN_PASSWORD` = 你的管理密码（第一次启动时用）
   - `DATA_DIR` = `./data`
5. 点 **Create Web Service**，等 1–2 分钟构建完，打开 `https://你的名字.onrender.com`。

**或者更省事**：仓库里已经有 `render.yaml`，在 Render 里选 **New → Blueprint** 指向仓库，它会自动读这个文件建服务。

### 第 3 步：必须知道的免费档限制

| 限制 | 后果 | 怎么办 |
|---|---|---|
| 15 分钟没人访问会休眠 | 客户第一次打开要等约 1 分钟 | 升级到 `0.5c-512mb`（$7/月） |
| 文件系统是临时的 | **重新部署后 `data/` 会被清空** | 见下面那条，或定期导出备份 |
| 每月 750 小时免费额度 | 用完当月服务被暂停 | 别跑多个免费服务 |

**想数据不丢**：把实例升级到付费档，然后在 Render 的服务设置里挂一个 Persistent Disk：
- Name：`peiwan-data`，Mount Path：`/var/data`，Size：1 GB（$0.25/月）
- 同时把环境变量 `DATA_DIR` 改成 `/var/data`

（`render.yaml` 里这段配置已经写好并注释掉了，取消注释即可。）

## 七、常见改动怎么做

| 想改什么 | 改哪里 |
|---|---|
| 首页文字、报价、微信号 | 后台 →「资料与报价」，**不用改代码** |
| **主页背景图 / 首屏图片 / 头像** | 后台 →「资料与报价」→ 主页图片（上传即用，可调压暗程度） |
| 分享到微信/QQ 的标题和简介 | 自动取「名字 + 一句话简介」和「首页公告」，在后台改完立刻生效 |
| 分享到微信的缩略图 | 自动取「头像 → 首屏图 → 展示墙第一张公开图 → 自带分享图」，也是后台改完就变 |
| 配色（现在是深色 + 荧光绿） | `static/style.css` 最上面 `:root` 里的 `--accent` 等 |
| 背景图的压暗渐变 | `static/style.css` 的 `.site-bg::after` |
| 时间表显示几天 | `app.py` 的 `DAYS_SHOWN` |
| 一次最多能选几小时 | `app.py` 的 `MAX_SELECT_HOURS`（前端 `site.js` 里也有一个 `MAX_HOURS`，一起改） |
| 上传图片的压缩尺寸 | `static/admin.js` 的 `compressImage()` 里 `1600` 和 `0.86` |
| 密码登录有效期 | `app.py` 的 `SESSION_HOURS` |
| 加一个"关于我"的板块 | `templates/index.html` 复制一个 `<section>`，`site.js` 里加渲染函数 |

## 八、排错

| 现象 | 原因 / 解决 |
|---|---|
| `python app.py` 报 `Address already in use` | 8123 端口被占了：`set PORT=9000 && python app.py` |
| 打开主页一片空白 | 按 F12 看 Console 报错；多半是 `data/` 没写权限 |
| 后台登录后一直跳回登录页 | 浏览器禁用了 Cookie；换浏览器或关掉无痕模式 |
| 客户说"看到的时间是灰色的点不动" | 那格子是 `rest`（休息）或 `past`（已过去），正常 |
| 改了 `app.py` 没生效 | 需要重启服务（`Ctrl+C` 后重新 `python app.py`） |
| 网页样式错乱 | 强制刷新：`Ctrl + F5` |

跑一遍自动测试，能立刻知道有没有改坏：

```bat
python tests\run_tests.py
```

它会**另起一个临时实例、用独立的数据目录**（`.testdata/`），测完自动删掉——
**你 `data/` 里的真实预约记录不会被碰到**。跑完看到 `通过 119 项，失败 0 项` 就说明一切正常。

自检一共跑三个阶段，全是自动的：

| 阶段 | 验的是什么 |
|---|---|
| 1. 接口测试（119 项） | 每个接口的正常路径 + 错误路径 |
| 2. 重启测试（5 项） | 关掉网站再启动：**登录状态还在、预约记录还在** |
| 3. 并发测试 | 8 个客户同时刷时间表 + 你在后台锁定/取消，**不能出现任何报错** |

单独跑并发测试（网站要已经在运行）：

```bat
set TEST_BASE=http://127.0.0.1:8123
set TEST_PASSWORD=你的密码
python tests\test_concurrency.py
```

### 部署完之后：线上体检（只读，不改数据）

```bat
python tests\check_deployed.py https://你的服务名.onrender.com
```

26 项检查：页面、微信分享卡片、时间表接口、后台是否被保护、静态资源、保活接口、
响应速度、HTTPS。看到 `通过 26 项 | 失败 0 项` 就放心了。

> ⚠️ **`test_api.py` 不能对着线上站点跑**：它会改管理密码、覆盖展示墙和资料。
> 脚本里已经加了保护——地址不是本机就直接拒绝运行（除非你明确设 `ALLOW_REMOTE_TESTS=1`）。

测试支持四个环境变量，方便测部署后的站点：

| 变量 | 默认 | 用途 |
|---|---|---|
| `TEST_BASE` | `http://127.0.0.1:8123` | 要测哪个地址 |
| `TEST_PASSWORD` | `baixu123` | 管理密码（改过就设这个） |
| `TEST_DATA_DIR` | 项目里的 `data` | 图片目录在哪（部署后是持久磁盘的路径） |
| `TEST_PORT` | `8199` | 自检时临时实例用哪个端口 |

## 九、接下来可以学什么

1. **加"预约申请"存档**：客户提交后先存成 `pending`，你在后台看到申请列表再一键转成预约（就不依赖微信文案了）。
2. **加通知**：客户提交时用 Server酱 / 邮件给你推一条消息。
3. **换数据库**：SQLite 换成 Render Postgres，多实例部署也不怕。
4. **加统计**：本月接单多少小时、收入多少。
5. **把前端换成框架**（Vue / React）：现在这套原生 JS 的好处是"打开就是全部代码"，学会之后再上框架不迟。
