# 练习手册 · 改一处、看一眼、学一点

这份手册的目标不是"读完就懂"，而是**手上有动作**。每个练习都告诉你：
改哪里 → 预期看到什么 → 怎么验证 → 想撤销怎么改回去。

**开工前**：先双击 `start.bat` 把网站跑起来，浏览器打开 <http://127.0.0.1:8123>。
改完 `.py` 文件要**重启**（Ctrl+C 后重新运行）；改 `.js` / `.css` / `.html` 只要 **Ctrl+F5 强制刷新**。

---

## 练习 1：让时间表从 7 天变成 14 天（5 分钟）

**改哪里**：`app.py` 第 54 行附近

```python
DAYS_SHOWN = 7          →   DAYS_SHOWN = 14
```

**预期**：主页时间表上面的日期标签从 7 个变成 14 个。

**验证**：重启后打开主页，或用命令行确认格子数：

```bat
python -c "import urllib.request,json;print(len(json.load(urllib.request.urlopen('http://127.0.0.1:8123/api/public'))['slots']))"
```

应该输出 `336`（14 × 24）。

**学到了**：前端格子数不是写死的，是后端算好发过来的。

## 练习 3：看一次"前端怎么和后端说话"（10 分钟，最重要）

1. 打开主页，按 **F12** → 切到 **Network（网络）** 面板 → 勾选 **Preserve log**
2. 刷新页面，找到 `api/public` 这条请求 → 点 **Response**，看到那 168 个格子

```json
{ "start": 1791734400000, "end": 1791738000000, "status": "free" }
```

3. 在时间表上点几个格子，观察新出现的 `api/availability?hours=...` 请求
4. 点「下一步：选择模式」，看它又核对了一次空档（防止被人抢先）
5. 填个联系方式 → 点「立即锁定时间」，会看到一条 **`api/book`** 的 POST 请求，
   点开它的 Response 就是"锁了哪几段、多少钱、给客户的文案"

**学到了**：网页不是"魔法"，它只是不停地在问服务器要数据。你以后调任何网站都能这样看。

## 练习 4：把"停接"开关玩一遍（5 分钟）

1. 后台 →「资料与报价」→ 取消勾选 **开放接单** → 保存
2. 回主页，空闲格子应该变成灰色 `停接`
3. 再勾回来 → 恢复 `可预约`

**验证**：也可以在后台「预约与时间」里看"今日可预约"的小时数变化。

**学到了**：`app.py` 里 `slot_status()` 那 12 行判断顺序的作用——
它先看时间过没过、再看有没有被锁定、再看休息规则、最后才看总开关。

## 练习 5：加一条"每周三全天休息"（5 分钟）

1. 后台 →「预约与时间」→ 固定休息规则
2. 重复星期只勾 **周三**，开始 `00:00` 到 `24:00`，备注"固定休息日"
3. 保存后回主页翻到周三那一列

**预期**：周三 24 个格子全部变成"休息"，客户点不动。

**验证**：删掉这条规则，周三立刻恢复。

**学到了**：规则是"算"出来的，不是"改数据"改出来的——所以删掉规则就立刻复原。

## 练习 6：备份 → 清空 → 恢复（10 分钟，强烈建议做一次）

这是**保命练习**。Render 免费实例每次重新部署都会清空数据，你必须亲手跑通一遍：

1. 后台 →「安全与备份」→ **下载备份 JSON**，存到桌面
2. 关掉网站（关掉黑窗口）→ **删掉整个 `data` 文件夹** → 重新 `start.bat`
3. 打开主页：展示墙空了、预约记录没了（模拟"被清空"）
4. 后台 →「从备份恢复」→ 选刚才那个 JSON → 确认
5. 主页刷新：数据回来了，图片也回来了

**学到了**： SQLite 就一个文件、图片就一个文件夹，备份 = 一个 JSON。

## 练习 8：换主页背景图（10 分钟，纯后台操作）

**为什么要做这个**：网站**开箱自带一张默认背景图**（`static/img/default-bg.jpg`，深色战术风：
斜向网格 + 等高线 + 雷达环），所以不再是"一张图都没有"的白板。但它终究是通用图，
换成你自己的游戏截图或立绘，效果会好得多。

1. 后台 →「资料与报价」→ 找到 **主页图片**
2. **主页背景图** → 选一张横图（建议 1920×1080 左右，游戏截图或官方宣传图都行）
   - 选完会自动压缩并上传，提示"已上传，记得点保存"
3. **首屏图片** → 选一张竖图/方图（比如干员立绘），它会出现在大标题旁边
4. **头像** → 选一张你的头像（会显示在"关于我"板块）
5. 拖一下 **背景压暗程度** 滑块：数字越大背景越暗、文字越清楚（默认 72%）
6. 点最下面的 **保存全部资料** → 回主页 Ctrl+F5 强制刷新

**预期**：背景换成你自己的图，标题区右边出现首屏图，文字依然清晰可读。

**不想用图片了**：点对应的「清除 XX」按钮 → 保存 → 主页恢复成自带的默认背景图。

**顺带试一下**：把 `static/img/default-bg.jpg` 改名（比如叫 `old.jpg`），刷新主页，
看默认背景是不是没了——这能让你彻底搞懂"CSS 引用的图片路径"是怎么回事。

**学到了**：图片不是"存进数据库"的，而是**存成 `data/uploads/` 里的文件**，
数据库里只记一个网址（`/api/media/xxxx.webp`）。这就是为什么备份要连图片一起打包。

**顺带一提**：你在这三张图里传的图，**也会自动变成微信分享卡片的缩略图**，优先级是
`头像 → 首屏图 → 展示墙第一张公开图 → 自带的分享图`。所以传完头像后，
把网址发到微信里看一眼，卡片上的小图应该就是你的头像了。

## 练习 9（重要）：搞清楚"图片放哪里"的区别

网站里的图片有两个可能的家，**搞混了会丢图**：

| 放哪 | 怎么放 | 优点 | 缺点 |
|---|---|---|---|
| `data/uploads/`（现在后台走的就是这条） | 后台点上传 | 随时换，不用改代码 | **免费的 Render 重新部署会清空**，要配持久磁盘或勤备份 |
| `static/img/` 文件夹（跟着代码走） | 把图片拷进 `static/img/`，在字段里填 `/static/img/bg.jpg` | 跟着 Git 仓库走，重新部署不会丢 | 换图要重新上传 GitHub / 重新部署 |
| 外部图床网址 | 直接在字段里填 `https://...` | 不占你的空间 | 依赖别人的网站，图挂了你的页面就空一块 |

**建议怎么做**：

- **天天换的**（客户截图、老板评价）→ 放 `data/uploads/`，走后台，定期导出备份
- **基本不动的**（背景图、首屏图、头像）→ 把文件放进 `static/img/`，
  然后在「主页背景图」那个输入框里填 `/static/img/bg.jpg`（这三个字段都支持直接填网址，
  所以你也可以填外部图床的地址）

**验证**：打开主页按 F12 → Network → 筛 `media`，能看到每张图从哪加载。

## 练习 10（进阶）：调换判断优先级

把 `app.py` 里 `slot_status()` 的 `if not accepting` 那两行**移到 `for rule in rules` 循环之前**，
重启，然后：

1. 关掉「开放接单」
2. 主页看：现在休息规则不再单独显示，全部统一变成"停接"

**想通了什么**：业务规则 = 一堆 `if` 的**顺序**。顺序变了，行为就变了。
这就是你朋友那套网站和我们这套唯一"有技术含量"的地方。
